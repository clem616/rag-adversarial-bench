# rag-adversarial-bench

An eight-pillar adversarial evaluation framework for Retrieval-Augmented Generation systems.

Plug in your RAG system, run the benchmark, get a dual Retrieval / Generation scorecard. The Medical reference dataset (FDA guidance + PubMedQA) is included as the baseline instantiation. Bring your own domain dataset generated by [`domain-ingestion-engine`](https://github.com/<!-- TODO -->/domain-ingestion-engine).

---

## Install

```bash
pip install rag-adversarial-bench
```

Dependencies: `domain-ingestion-engine`, `faiss-cpu`, `sentence-transformers`, `langchain-community`, `anthropic`. Python 3.10+.

## Quickstart: benchmark your RAG system

**Step 1** — implement the `RAGSystem` interface (two methods):

```python
from rag_bench.systems.base import RAGSystem

class MySystem(RAGSystem):
    def retrieve(self, query: str, top_k: int = 5) -> list[dict]:
        # return list of {"doc_id": str, "text": str, "score": float}
        ...

    def generate(self, query: str, context: list[dict]) -> str:
        # return answer string
        ...
```

**Step 2** — run the benchmark:

```bash
python -m rag_bench.run_benchmark \
  --system my_module.MySystem \
  --dataset rag_bench/datasets/medical \
  --output results/my_system.json
```

## Free tier — no API key required

Four of the eight pillars require no LLM judge. Run them at zero cost:

```bash
python -m rag_bench.run_benchmark \
  --system my_module.MySystem \
  --dataset rag_bench/datasets/medical \
  --output results/my_system_free.json \
  --skip-judge
```

This evaluates P1 (Embedding Calibration), P2 (IR Metrics), P4 (OOD Safe Refusal), and P5 (Multi-Turn Coherence). Scores are renormalized automatically over the four available pillars.

---

## Eight pillars

| ID | Pillar | Tier | Requires judge |
|---|---|---|---|
| P1 | Embedding Calibration | Retrieval | No |
| P2 | IR Metrics (Hit@5, MRR) | Retrieval | No |
| P7 | Position Bias | Retrieval | Yes |
| P8 | Distractor Injection | Retrieval | Yes |
| P3 | Monte Carlo Stability | Generation | Yes |
| P4 | OOD Safe Refusal | Generation | No |
| P5 | Multi-Turn Coherence | Generation | No |
| P6 | Poisoned Context Grounding | Generation | Yes |

**Retrieval Score** = weighted average of P1/P2/P7/P8  
**Generation Score** = weighted average of P3/P4/P5/P6  
**Overall Score** = (Retrieval + Generation) / 2

## LangChain-FAISS reference system

A ready-to-run reference implementation is included:

```bash
python -m rag_bench.run_benchmark \
  --system rag_bench.systems.langchain_faiss.LangChainFAISSSystem \
  --dataset rag_bench/datasets/medical \
  --output results/langchain_faiss.json
```

This builds a FAISS index from the dataset's `ground_truth_context` fields — no external data download required. Scores: Overall 90.7/100 (Retrieval 93.6, Generation 87.8) with `claude-sonnet-4-6` judge, 5 Monte Carlo passes.

## Judge configuration

The Generation Tier pillars (P3/P6/P7/P8) use an independent LLM judge, separate from the system under test.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
# or Azure AI Foundry:
export LLM_BASE_URL_CLAUDE=https://your-resource.services.ai.azure.com/anthropic
export LLM_API_KEY_CLAUDE=...

# Control cost via model and pass count:
JUDGE_MODEL=claude-haiku-4-5 MONTE_CARLO_PASSES=3 python -m rag_bench.run_benchmark ...
JUDGE_MODEL=claude-sonnet-4-6 MONTE_CARLO_PASSES=5 python -m rag_bench.run_benchmark ...  # official run
```

## CLI reference

```
python -m rag_bench.run_benchmark [OPTIONS]

  --system TEXT              Dotted path to RAGSystem subclass (e.g. my_module.MySystem)
  --dataset PATH             Directory containing ground_truth_*.json files
  --output PATH              Where to write the results JSON
  --skip-judge               Run P1/P2/P4/P5 only (no API key required)
  --monte-carlo-passes INT   Number of independent answer passes for P3 [default: 5]
  --judge-model TEXT         LLM judge model [default: claude-haiku-4-5]
  --top-k INT                Retrieval depth [default: 5]
```

## v2 roadmap — call for contributions

This is a v1 release. Open problems we are inviting the community to address:

- **Second domain dataset** — a Legal or Finance instantiation of `domain-ingestion-engine` that validates domain-agnostic generalisability
- **Human GT audit** — 50-case spot-check with inter-annotator agreement on the Medical IR cases
- **Alternative judge models** — replication with GPT-4o, Gemini, or a local open-weight model to quantify judge-model sensitivity
- **Larger adversarial splits** — expanding poisoned/multiturn sets from 20 to 100+ cases to reduce confidence intervals
- **Additional reference systems** — BM25, hybrid dense+sparse, any commercial RAG API

Issues, leaderboard submissions, and domain PRs welcome.
